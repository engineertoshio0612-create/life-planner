# CSVインポート テスト設計

## 1. 概要

本ディレクトリでは、CSVインポート関連APIに対するテスト方針および主要なテスト観点を定義する。

対象APIは以下とする。

- CSV-001 月末資産残高CSVテンプレート取得
- CSV-002 月末資産残高CSVプレビュー
- CSV-003 月末資産残高CSV登録
- CSV-004 商品別月末評価額CSVテンプレート取得
- CSV-005 商品別月末評価額CSVプレビュー
- CSV-006 商品別月末評価額CSV登録

CSVインポートでは、以下の一連の処理が整合した仕様で動作することを確認する。

```text
テンプレート取得
    ↓
CSV入力
    ↓
プレビュー
    ↓
入力値・業務ルール検証
    ↓
登録
    ↓
最新状態で再検証
    ↓
一括登録
```

テンプレート取得では、CSVヘッダー、項目順序、Content-Type、利用者固有データが含まれないこと、副作用が発生しないことを確認する。また、テンプレートのCSV Definitionが後続のプレビュー・登録APIと一致することを保証する。

プレビューでは、CSV構造、入力値、利用者境界、資産口座・保有商品、対象年月時点の有効性、既存データ、CSV内重複などを検証し、`canImport`、CSV全体エラー、行単位エラーが正しく返却されることを確認する。

プレビューは参照専用処理であるため、月末資産状況を含む業務データが作成・更新されないことを保証する。

登録では、プレビュー結果を信頼せず、実行時点の最新状態で同じ業務ルールが再検証されることを確認する。1件でも登録できない行が存在する場合は部分登録を行わず、CSV全体を失敗させる。

```text
全件検証成功
    → トランザクション
    → 一括登録
    → COMMIT

1件以上検証失敗
    → 登録なし

登録途中で例外
    → ROLLBACK
```

また、利用者境界、論理削除、同時実行、UNIQUE制約、再送時の重複防止、トランザクションによる原子性を確認する。

複数行CSVでは、資産口座、保有商品、既存データなどの取得でN+1が発生しないことも確認する。

個別APIの正常系・異常系・業務ルール・副作用・性能・同時実行などの詳細なテストケースについては、各APIのテスト設計書を参照する。
