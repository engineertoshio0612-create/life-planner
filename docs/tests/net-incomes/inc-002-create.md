# INC-002 手取り収入登録

## 1. 概要

本ドキュメントでは、
INC-002 手取り収入登録APIに対する
テスト方針および
主要なテスト観点を定義する。

本APIでは、
操作対象となる利用者について、
指定した対象年月の手取り収入を
正しく新規登録できることを確認する。

テストでは、
手取り収入の登録だけでなく、
以下の観点を確認する。

* 対象年月の重複制御
* 手取り収入金額のバリデーション
* 備考の入力および正規化
* リクエストボディの制約
* 利用者境界
* `X-User-Id`による利用者特定
* トランザクション
* 同時実行時の重複防止
* レスポンス契約
* 異常発生時のエラーレスポンス

手取り収入は、
同一利用者について
対象年月ごとに1件のみ登録できることを確認する。

すでに登録されている対象年月への
重複登録については、
アプリケーションによる事前チェックだけでなく、
同時実行時にもデータベースの制約によって
重複データが作成されないことを確認する。

対象年月に収入が発生しなかった場合は、
未登録とはせず、
金額`0`の有効な手取り収入として
登録できることを確認する。

また、
利用者IDはリクエストボディから受け取らず、
`X-User-Id`から特定された
操作対象利用者へ正しく紐づくことを確認する。

登録途中で例外が発生した場合は、
トランザクションによって
登録内容がロールバックされることを確認する。

レスポンスについては、
IDの文字列化、
`YYYY-MM`形式の対象年月、
camelCaseのフィールド名など、
API共通方針および
API詳細設計で定義された
レスポンス契約を満たすことも
テスト対象とする。


---

## 2. テスト観点

### 2.1 正常系

- 手取り収入を登録できること
- 金額が0円でも登録できること
- 備考なしで登録できること
- 備考ありで登録できること
- `201 Created`で返却されること
- 登録後の内容がレスポンスへ返却されること

### 2.2 利用者境界

- 操作対象利用者の手取り収入として登録されること
- 他利用者の手取り収入として登録されないこと
- userIdをリクエストから指定できないこと

### 2.3 対象年月

- 新しい対象年月を登録できること
- 同一対象年月は登録できないこと
- 同一利用者で対象年月重複時は409となること

### 2.4 金額

- 正常な整数値を登録できること
- 0円を登録できること
- 負数でエラーとなること
- 小数でエラーとなること
- 最大値を超える場合にエラーとなること

### 2.5 備考

- 最大文字数以内なら登録できること
- 最大文字数超過でエラーとなること
- 空文字がNULLへ正規化されること

### 2.6 リクエストボディ

- 必須項目不足でエラーとなること
- 未定義項目を指定するとエラーとなること
- idを指定するとエラーとなること
- userIdを指定するとエラーとなること
- createdAtを指定するとエラーとなること
- updatedAtを指定するとエラーとなること

### 2.7 ヘッダー

- X-User-Id未指定でエラーとなること
- 利用者ID形式不正でエラーとなること
- 存在しない利用者IDでエラーとなること
- 論理削除済み利用者でエラーとなること

### 2.8 トランザクション

- 登録途中で例外が発生した場合にロールバックされること
- 重複登録時に登録されないこと

### 2.9 同時実行

- 同一対象年月へ同時登録した場合に1件のみ成功すること
- 後続リクエストが409となること

### 2.10 レスポンス契約

- JSONフィールド名がcamelCaseであること
- 手取り収入IDが文字列で返却されること
- 対象年月がYYYY-MM形式で返却されること
- 金額が整数で返却されること
- memoがNULLを許容すること
- userIdがレスポンスへ含まれないこと
- createdAtがレスポンスへ含まれないこと
- updatedAtがレスポンスへ含まれないこと

### 2.11 異常系

- 想定外の例外で500となること
- 共通エラーレスポンス形式で返却されること
- リクエストIDがレスポンスとログで一致すること
- SQLやスタックトレースがレスポンスへ含まれないこと
