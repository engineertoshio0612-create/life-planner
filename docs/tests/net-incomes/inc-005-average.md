# INC-005 平均手取り収入取得

## 1. 概要

本ドキュメントでは、
INC-005 平均手取り収入取得APIに対する
テスト方針および
主要なテスト観点を定義する。

本APIでは、
操作対象となる利用者について、
指定した判定対象年月の直前にあたる
連続する3か月の手取り収入から、
平均手取り収入を
正しく算出できることを確認する。

テストでは、
平均手取り収入の取得だけでなく、
以下の観点を確認する。

* 算出対象となる3か月の特定
* 平均手取り収入の算出ロジック
* 金額0円の月の扱い
* 手取り収入データ不足時の制御
* 利用者境界
* 判定対象年月のバリデーション
* `X-User-Id`による利用者特定
* レスポンス契約
* 異常発生時のエラーレスポンス

平均値の算出では、
判定対象年月自身を含めず、
その直前にあたる
連続する3か月のみが
算出対象となることを確認する。

手取り収入金額が0円の月についても、
データ不足とは判定せず、
有効な手取り収入として
平均値の算出対象に含まれることを確認する。

算出対象となる3か月のうち、
1か月でも手取り収入が
登録されていない場合は、
平均値を算出せず、
`NET_INCOME_DATA_INSUFFICIENT`が
返却されることを確認する。

また、
操作対象利用者の手取り収入のみを使用し、
他利用者のデータが
平均値の算出へ含まれないことを確認する。

レスポンスについては、
`targetYearMonth`、
`averageAmount`および
`calculatedMonths`が、
API共通方針および
API詳細設計で定義された形式で
返却されることを確認する。

平均手取り収入は
データベースへ保存せず、
取得時点の手取り収入をもとに
都度算出された結果が
返却されることもテスト対象とする。


---

## 2. テスト観点

### 2.1 正常系

- 連続する3か月の手取り収入から平均値を算出できること
- 判定対象年月自身を平均値へ含めないこと
- 平均手取り収入を取得できること
- `200 OK`で返却されること

### 2.2 算出ロジック

- 3か月すべての手取り収入から平均値を算出すること
- 手取り収入が0円の月も平均値へ含めること
- 平均値が整数で返却されること
- 算出対象年月一覧が正しく返却されること

### 2.3 データ不足

- 算出対象3か月のうち1か月不足すると422となること
- 算出対象3か月のうち2か月不足すると422となること
- 算出対象3か月すべて不足すると422となること
- `NET_INCOME_DATA_INSUFFICIENT`が返却されること

### 2.4 利用者境界

- 操作対象利用者の手取り収入のみ算出対象となること
- 他利用者の手取り収入を平均値へ含めないこと

### 2.5 判定対象年月

- `YYYY-MM`形式で取得できること
- 不正な形式では400となること
- 判定対象年月自身を算出対象へ含めないこと
- 判定対象年月直前の連続する3か月を使用すること

### 2.6 ヘッダー

- `X-User-Id`未指定で400となること
- 利用者ID形式不正で400となること
- 存在しない利用者IDで404となること
- 論理削除済み利用者で404となること

### 2.7 レスポンス契約

- JSONフィールド名がcamelCaseであること
- `targetYearMonth`が`YYYY-MM`形式で返却されること
- `averageAmount`が整数で返却されること
- `calculatedMonths`が3件返却されること
- `data`オブジェクトで返却されること

### 2.8 異常系

- 想定外の例外で`500 Internal Server Error`となること
- 共通エラーレスポンス形式で返却されること
- エラーレスポンスとログで同じリクエストIDが記録されること
- SQLやスタックトレースなどの内部情報がレスポンスへ含まれないこと
