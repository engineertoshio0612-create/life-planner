# INC-003 手取り収入詳細取得

## 1. 概要

本ドキュメントでは、
INC-003 手取り収入詳細取得APIに対する
テスト方針および
主要なテスト観点を定義する。

本APIでは、
操作対象となる利用者に登録された
指定の手取り収入を
正しく取得できることを確認する。

テストでは、
手取り収入詳細の取得だけでなく、
以下の観点を確認する。

* 手取り収入IDによる取得
* 利用者境界
* `X-User-Id`による利用者特定
* データ不存在時の制御
* レスポンス契約
* 異常発生時のエラーレスポンス

手取り収入金額が0円の場合も、
未登録とは区別し、
有効な手取り収入として
取得できることを確認する。

備考については、
設定されている場合だけでなく、
未設定の`null`についても
正常に返却されることを確認する。

手取り収入の取得では、
手取り収入IDだけでなく
操作対象利用者との帰属関係を確認し、
他利用者に登録された手取り収入を
取得できないことをテストする。

存在しない手取り収入IDと
他利用者に帰属する手取り収入IDについては、
いずれも対象データを公開せず、
`404 Not Found`として扱われることを確認する。

レスポンスについては、
IDの文字列化、
`YYYY-MM`形式の対象年月、
camelCaseのフィールド名、
`memo`のNULL許容など、
API共通方針および
API詳細設計で定義された
レスポンス契約を満たすことを確認する。

また、
想定外の例外発生時には、
共通エラーレスポンス形式で処理され、
SQLやスタックトレースなどの
内部情報が外部へ公開されないことも
テスト対象とする。

---

## 2. テスト観点

### 2.1 正常系

- 指定した手取り収入を取得できること
- 金額が0円でも取得できること
- 備考が未設定でも取得できること
- 備考が設定されている場合も取得できること
- `200 OK`で返却されること

### 2.2 利用者境界

- 操作対象利用者の手取り収入のみ取得できること
- 他の利用者の手取り収入は取得できないこと
- 他利用者のデータがレスポンスへ含まれないこと

### 2.3 手取り収入ID

- 存在する手取り収入IDを指定すると取得できること
- 存在しない手取り収入IDを指定すると404となること
- 他利用者の手取り収入IDを指定すると404となること
- 手取り収入ID形式不正で400となること

### 2.4 ヘッダー

- `X-User-Id`未指定でエラーとなること
- 利用者ID形式不正でエラーとなること
- 存在しない利用者IDでエラーとなること
- 論理削除済み利用者でエラーとなること

### 2.5 レスポンス契約

- JSONフィールド名がcamelCaseであること
- 手取り収入IDが文字列で返却されること
- 対象年月が`YYYY-MM`形式で返却されること
- 金額が整数で返却されること
- `memo`がNULLを許容すること
- `userId`がレスポンスへ含まれないこと
- `createdAt`がレスポンスへ含まれないこと
- `updatedAt`がレスポンスへ含まれないこと
- `data`オブジェクトで返却されること

### 2.6 異常系

- 想定外の例外で`500 Internal Server Error`となること
- 共通エラーレスポンス形式で返却されること
- エラーレスポンスとログに同じリクエストIDが記録されること
- SQLやスタックトレースなどの内部情報がレスポンスへ含まれないこと
