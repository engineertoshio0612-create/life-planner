# INC-001 手取り収入一覧取得

## 1. 概要

本ドキュメントでは、
INC-001 手取り収入一覧取得APIに対する
テスト方針および
主要なテスト観点を定義する。

本APIでは、
操作対象となる利用者に登録された
手取り収入を対象年月単位で取得し、
一覧として正しく返却できることを確認する。

テストでは、
手取り収入一覧の取得だけでなく、
以下の観点を確認する。

* 対象年月による並び順
* ページネーション
* 利用者境界
* データ未登録時のレスポンス
* クエリパラメータのバリデーション
* `X-User-Id`による利用者特定
* レスポンス契約
* 異常発生時のエラーレスポンス

手取り収入金額が0円の場合も、
未登録とは区別し、
有効な手取り収入として
一覧へ含まれることを確認する。

また、
すべての取得処理において
操作対象利用者の境界が維持され、
他利用者の手取り収入が
レスポンスへ含まれないことを確認する。

レスポンスについては、
IDの文字列化、
`YYYY-MM`形式の対象年月、
camelCaseのフィールド名、
`memo`のNULL許容など、
API共通方針および
API詳細設計で定義された
レスポンス契約を満たすことを確認する。

想定外の例外発生時には、
共通エラーレスポンス形式で
`500 Internal Server Error`が返却され、
SQLやスタックトレースなどの
内部情報が外部へ公開されないことも
テスト対象とする。


---

## 2. テスト観点

### 2.1 正常系

- 手取り収入一覧を取得できること
- 手取り収入が1件の場合でも取得できること
- 手取り収入が複数件の場合でも取得できること
- 対象年月降順で取得できること
- 対象年月昇順で取得できること
- 金額が0円の手取り収入も取得できること
- 備考が未設定でも取得できること
- `200 OK`で返却されること

### 2.2 利用者境界

- 操作対象利用者の手取り収入のみ取得できること
- 他の利用者の手取り収入を取得できないこと
- 他利用者のデータがレスポンスへ含まれないこと

### 2.3 ページネーション

- 1ページ目を取得できること
- 指定したページを取得できること
- `perPage`どおりの件数で取得できること
- 最終ページを超えた場合は空配列を返却すること
- `meta`がAPI共通方針どおり返却されること

### 2.4 並び順

- `order=asc`で対象年月昇順となること
- `order=desc`で対象年月降順となること
- `order`未指定時は降順となること

### 2.5 データなし

- 手取り収入が未登録の場合でも正常終了すること
- `data`が空配列で返却されること
- `meta.total`が0となること

### 2.6 パラメータ

- `page`が不正な場合にエラーとなること
- `perPage`が不正な場合にエラーとなること
- `order`が不正な場合にエラーとなること

### 2.7 ヘッダー

- `X-User-Id`未指定でエラーとなること
- `X-User-Id`形式不正でエラーとなること
- 存在しない利用者IDでエラーとなること
- 論理削除済み利用者でエラーとなること

### 2.8 レスポンス契約

- JSONフィールド名がcamelCaseであること
- 手取り収入IDが文字列で返却されること
- 対象年月が`YYYY-MM`形式で返却されること
- 金額が整数で返却されること
- `memo`がNULLを許容すること
- `userId`がレスポンスへ含まれないこと
- `createdAt`がレスポンスへ含まれないこと
- `updatedAt`がレスポンスへ含まれないこと
- `data`が配列で返却されること
- `meta`がAPI共通方針どおり返却されること

### 2.9 異常系

- 想定外の例外発生時に`500 Internal Server Error`となること
- 共通エラーレスポンス形式で返却されること
- エラーレスポンスとログに同じリクエストIDが記録されること
- SQLやスタックトレースなどの内部情報がレスポンスへ含まれないこと
