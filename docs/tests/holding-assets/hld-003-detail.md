# HLD-003 保有商品詳細取得

## 1. 概要

本ドキュメントでは、HLD-003 保有商品詳細取得APIに対するテスト方針および主要なテスト観点を定義する。

本APIでは、操作対象となる利用者に帰属する保有商品の詳細情報を取得する処理を検証する。

利用中の保有商品だけでなく、無効化済みの保有商品も取得対象とし、所属する資産口座が無効化済みの場合についても資産口座情報を取得できることを確認する。

主に以下を確認する。

* 保有商品詳細の正常取得
* 利用者境界
* 保有商品の利用状態
* 所属資産口座との関連
* 備考の返却形式
* `X-User-Id`の検証
* 保有商品IDの検証
* レスポンス契約
* 異常系および共通エラーレスポンス

特に利用者境界については、他利用者に帰属する保有商品を取得できず、対象が存在しない場合と同様に`404 Not Found`として扱われることを確認する。

また、`deleted_at`の状態から`isEnabled`が正しく変換されること、無効化済み保有商品でも詳細を取得できること、および`deletedAt`などの内部管理情報がレスポンスへ公開されないことを検証する。

正常終了時は、`200 OK`が返却され、保有商品および所属資産口座の情報がAPI共通方針に従ったレスポンス形式で返却されることを確認する。

---

## 2. テスト観点

### 2.1 正常系

- 利用中の保有商品を取得できること
- 無効化済みの保有商品を取得できること
- 保有商品名が返却されること
- 商品種別が返却されること
- 所属資産口座IDが返却されること
- 所属資産口座名が返却されること
- 利用開始年月が返却されること
- 備考が返却されること
- 利用状態が返却されること
- 保有商品IDが文字列で返却されること
- 所属資産口座IDが文字列で返却されること

### 2.2 利用者境界

- 操作対象利用者に帰属する保有商品を取得できること
- 他の利用者に帰属する保有商品を取得できないこと
- 他の利用者に帰属する保有商品を指定した場合に`404 Not Found`となること
- 同じ保有商品IDが他利用者のデータとして誤って返却されないこと

### 2.3 利用状態

- `deleted_at`が`NULL`の場合に`isEnabled`が`true`となること
- `deleted_at`が設定されている場合に`isEnabled`が`false`となること
- `deletedAt`がレスポンスへ含まれないこと

### 2.4 所属資産口座

- 所属資産口座名を取得できること
- 所属資産口座が無効化済みでも資産口座名を取得できること
- 所属資産口座の利用状態がレスポンスへ含まれないこと
- 保有商品と所属資産口座の関連が正しいこと

### 2.5 備考

- 備考が登録されている場合に文字列で返却されること
- 備考が登録されていない場合に`null`で返却されること
- 備考未登録時に空文字を返さないこと

### 2.6 ヘッダー

- `X-User-Id`が指定されていない場合にエラーとなること
- `X-User-Id`の形式が不正な場合にエラーとなること
- 存在しない利用者IDの場合にエラーとなること
- 論理削除済み利用者IDの場合にエラーとなること

### 2.7 パスパラメータ

- 正しい保有商品IDで取得できること
- 保有商品IDの形式が不正な場合にエラーとなること
- 存在しない保有商品IDの場合に`404 Not Found`となること
- 無効化済みの保有商品IDでも取得できること

### 2.8 レスポンス契約

- 共通レスポンス形式に従っていること
- JSONフィールド名がcamelCaseであること
- `userId`がレスポンスへ含まれないこと
- `createdAt`がレスポンスへ含まれないこと
- `updatedAt`がレスポンスへ含まれないこと
- `deletedAt`がレスポンスへ含まれないこと
- データベースの数値コードがそのまま公開されないこと
- `data`がオブジェクトとして返却されること

### 2.9 異常系

- 想定外の例外発生時に`500 Internal Server Error`となること
- 共通エラーレスポンス形式で返却されること
- エラーレスポンスとログに同じリクエストIDが記録されること
- SQLやスタックトレースなどの内部情報がレスポンスへ含まれないこと
