# 保有商品 テスト設計

## 1. 概要

本ディレクトリでは、保有商品に関するAPIのテスト方針および主要なテスト観点を定義する。

対象APIは以下とする。

* HLD-001 保有商品一覧取得
* HLD-002 保有商品登録
* HLD-003 保有商品詳細取得
* HLD-004 保有商品更新
* HLD-005 保有商品無効化

保有商品APIでは、一覧取得、登録、詳細取得、更新および無効化までの一連の操作について、API詳細設計およびアーキテクチャ設計に従って正しく動作することを確認する。

## 2. 共通テスト方針

各APIでは、主に以下を確認する。

* 正常系
* 利用者境界
* 入力値・パスパラメータ・ヘッダーの検証
* 資産口座との関連および状態
* 保有商品の利用状態
* レスポンス契約
* 共通エラーレスポンス
* データベース整合性
* 想定外エラー発生時の処理

利用者境界では、`X-User-Id`で指定された操作対象利用者に帰属する保有商品のみ取得・登録・更新・無効化できることを確認する。

他利用者に帰属するリソースを指定した場合は、対象リソースの存在を推測できないレスポンスとなることを確認する。

## 3. 登録・更新

HLD-002では、商品単位で管理する有効な資産口座への登録、利用開始年月の整合性および同一資産口座内の商品名重複を確認する。

HLD-004では部分更新を前提とし、指定された項目のみが変更され、所属資産口座、利用開始年月および利用状態が変更されないことを確認する。

## 4. 無効化・履歴保持

HLD-005では、SoftDeletesによる論理削除が行われることを確認する。

無効化によって過去の商品別月末評価額、月末資産状況および目的達成判定履歴が変更・削除されないことを確認する。

通常更新と無効化は異なる業務操作として扱い、HLD-004とHLD-005の責務が分離されていることを確認する。

## 5. 個別テスト設計

各API固有の正常系、異常系、境界値、レスポンス契約およびデータベース検証については、各APIのテスト設計を参照する。
