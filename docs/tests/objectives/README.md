# 目的 テスト設計

## 1. 概要

本ディレクトリでは、
目的に関するAPIのテスト方針および主要なテスト観点を定義する。

目的は、
利用者が将来達成したい内容と必要支出額を管理し、
資産状況および手取り収入をもとに
目的達成可否を判定するために利用する。

対象APIは以下とする。

- OBJ-001 目的一覧取得
- OBJ-002 目的登録
- OBJ-003 目的詳細取得
- OBJ-004 目的更新
- OBJ-005 目的無効化
- OBJ-006 目的達成判定

---

## 2. テスト方針

目的APIでは、
各API固有の正常系・異常系に加えて、
以下の観点を共通して確認する。

- 操作対象利用者に帰属するデータのみ操作できること
- 他利用者の目的を参照・更新できないこと
- `X-User-Id`による利用者コンテキストが適用されること
- ID、年月、金額などが仕様に従って検証されること
- JSONフィールド名および型がAPI共通方針に従うこと
- 論理削除済みデータが適切に除外されること
- 想定外例外が共通エラーレスポンスへ変換されること
- 内部情報がレスポンスへ公開されないこと

---

## 3. API別の重点観点

OBJ-001およびOBJ-003では、
利用者境界、利用状態および参照可能範囲を確認する。

OBJ-002およびOBJ-004では、
入力値検証、目的名の重複、
更新対象項目およびトランザクションを確認する。

OBJ-005では、
`enabled`のみを変更すること、
論理削除とは区別されること、
過去の目的達成判定履歴へ副作用がないことを確認する。

OBJ-006では、
確定済み月末資産状況、
利用可能資産設定、
平均手取り収入および
翌月クレジットカード支払予定額を用いた判定計算を確認する。

また、
判定成功時に計算根拠を含む判定履歴が保存され、
判定失敗時には不完全な履歴が残らないことを確認する。
