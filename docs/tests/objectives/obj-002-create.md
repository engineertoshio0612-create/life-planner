# OBJ-002 目的登録

```md
## 1. 概要

操作対象となる利用者の目的を登録する。

目的には、
目的名、
実施予定年月、
必要支出額および
メモを登録できる。

登録された目的は、
目的達成判定の対象として利用される。

本APIでは、
入力された目的情報を検証し、
操作対象利用者に帰属する新しい目的として登録する。

登録直後の目的は利用中として扱う。

同一利用者に同名の有効な目的が
すでに存在する場合は、
重複登録を許可しない。

なお、
目的登録時点では目的達成判定は実行せず、
目的情報の登録のみを行う。

主に以下を確認する。

- 正常な目的情報を登録できること
- 登録した目的が操作対象利用者に帰属すること
- 入力値が仕様に従って検証されること
- 同一利用者に同名の有効な目的を重複登録できないこと
- 他利用者の目的と独立して登録できること
- 登録直後の目的が利用中として扱われること
- 同時登録時にもデータ整合性が維持されること
- 登録途中で例外が発生した場合に不完全なデータが残らないこと
- 登録結果がAPI仕様に従った形式で返却されること
```

---

## 2. テスト観点

詳細なテストケースは`docs/tests/backend/`で管理し、本API詳細設計では主要な確認事項のみ記載する。

### 2.1 正常系

* 必須項目を指定して目的を登録できること
* `memo`を指定して登録できること
* `memo`を省略または`null`として登録できること
* 登録した目的が操作対象利用者に帰属すること
* 登録時の目的が利用中として扱われること
* 登録成功時に`201 Created`が返却されること
* 登録した目的がレスポンスとして返却されること

### 2.2 バリデーション

* `name`の必須、型、空文字、最大文字数が検証されること
* `plannedYearMonth`の必須、型、年月形式および実在年月が検証されること
* `requiredExpense`の必須、整数、0以上が検証されること
* `memo`の型および最大文字数が検証されること

### 2.3 業務ルール

* 同一利用者に同名の有効な目的が存在する場合、登録できないこと
* 他利用者に同名の目的が存在しても登録できること
* 利用者IDをリクエストボディから指定できないこと
* 目的登録時に目的達成判定が実行されないこと

### 2.4 データ整合性

* 同一利用者・同一目的名の同時登録でも重複した目的が作成されないこと
* 登録処理中に例外が発生した場合、不完全な登録結果が残らないこと

利用者コンテキスト、共通エラー、共通レスポンス形式などの横断的なテストは、API共通テスト方針に従う。
