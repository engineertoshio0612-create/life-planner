# 月末資産状況 テスト設計

## 1. 概要

本ディレクトリでは、
月末資産状況に関するAPIの
テスト方針および主要な検証観点を定義する。

対象APIは以下とする。

- SNP-001 月末資産状況一覧取得
- SNP-002 月末資産状況作成
- SNP-003 月末資産状況詳細取得
- SNP-004 月末資産状況確定
- SNP-005 月末資産状況確定解除

月末資産状況は、
対象年月ごとの月末資産残高および
商品別月末評価額を管理する
親リソースとして扱う。

---

## 2. 共通テスト方針

各APIでは、
以下を共通して確認する。

- `X-User-Id` による利用者境界
- 他利用者データへアクセスできないこと
- ID・入力値のバリデーション
- HTTPステータスおよび独自エラーコード
- camelCaseによるレスポンス契約
- DB内部情報を外部へ公開しないこと
- 意図しない関連データへの副作用がないこと

存在しない月末資産状況と
他利用者に属する月末資産状況は、
必要に応じて同一の
`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`
として扱う。

---

## 3. API別主要観点

SNP-001では、
確定済み・未確定を含む一覧取得、
対象年月降順、
0件時の空配列、
参照による副作用がないことを確認する。

SNP-002では、
`targetYearMonth` の形式検証、
作成直後が未確定であること、
同一利用者・同一対象年月の重複防止、
UNIQUE制約による同時作成時の整合性を確認する。

SNP-003では、
`snapshotId` と利用者IDによる
詳細取得の境界、
確定状態に関係なく取得できること、
不要な関連明細を取得しないことを確認する。

SNP-004では、
月末資産残高・商品別月末評価額の充足、
対象年月時点の資産判定、
確定順序、
トランザクションおよび排他制御を確認する。

SNP-005では、
最新の確定済み月末資産状況のみ
確定解除できること、
残高・評価額・目的達成判定履歴を保持すること、
トランザクションおよび排他制御を確認する。

---

## 4. 異常系

想定外の例外では、
`500 Internal Server Error` と
共通エラーレスポンス形式で返却されることを確認する。

SQL、
PostgreSQL内部情報、
制約名、
スタックトレース、
内部例外メッセージは
レスポンスへ含めない。

更新系APIでは、
例外発生時にロールバックされ、
部分的な更新状態が残らないことを確認する。
