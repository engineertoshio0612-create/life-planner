# SNP-003 月末資産状況詳細取得

## 1. 概要

操作対象となる利用者について、
指定した月末資産状況の詳細情報を取得する。

本APIでは、
月末資産状況そのものの情報を取得する。

取得対象には、
確定済みおよび未確定の
月末資産状況を含む。

月末資産残高および
商品別月末評価額の明細は、
本APIでは返却しない。

---

## 2. ユースケース

利用者は、
指定した対象年月の
月末資産状況を確認する。

例えば、
以下のような場合に使用する。

- 月末資産状況詳細画面を表示する
- 対象年月を確認する
- 確定状態を確認する
- 月末資産残高入力画面へ遷移する
- 商品別月末評価額入力画面へ遷移する
- 確定または確定解除の操作対象を確認する

確定済み・未確定の
どちらの月末資産状況も
詳細表示できる。

---

## 3. エンドポイント

```http
GET /api/v1/month-end-asset-snapshots/{snapshotId}
```

---

## 4. HTTPメソッド

```text
GET
```

本APIは、指定した月末資産状況を参照する。

月末資産状況の作成、月末資産残高の登録・更新、商品別月末評価額の登録・更新、確定および確定解除は行わない。

---

## 5. 認証・利用者の扱い

Phase1では、認証機能を実装しない。

操作対象となる利用者は、`X-User-Id`リクエストヘッダーで指定する。

```http
X-User-Id: 1
```

指定された利用者に属する月末資産状況のみ取得できる。

他の利用者に属する月末資産状況は取得できない。

他の利用者に属する月末資産状況IDを指定した場合は、対象が存在しないものとして扱う。

利用者IDは、リクエストボディ、クエリパラメータまたはパスパラメータでは受け付けない。

月末資産状況を取得する際は、必ず以下を検索条件に含める。

```text
id = snapshotId
AND
user_id = 操作対象利用者ID
```

`X-User-Id`が指定されていない場合、形式が不正な場合、または指定された利用者が存在しない場合は、API共通方針に従ってエラーを返却する。

## 11. バリデーション

### 11.1 snapshotId

`snapshotId`は、
必須のパスパラメータとする。

以下を検証する。

- 指定されていること
- API共通方針で定めたID形式であること
- 正の整数として扱えること

正常例：

```text
1
12
123
```

不正例：

```text
0
-1
abc
1.5
```

`snapshotId`の形式が不正な場合は、
`VALIDATION_ERROR`
として扱う。

---

### 11.2 月末資産状況の存在確認

指定された`snapshotId`について、
以下の条件を満たす
月末資産状況が存在することを確認する。

```text
id = snapshotId
AND
user_id = 操作対象利用者ID
```

対象となる月末資産状況が
存在しない場合は、
`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`
として扱う。

確定済み・未確定の
どちらも取得対象とする。

---

### 11.3 利用者境界

月末資産状況の存在確認では、
`snapshotId`だけで検索しない。

必ず、
操作対象利用者IDを
検索条件に含める。

```text
id = snapshotId
AND
user_id = 操作対象利用者ID
```

他の利用者に属する
月末資産状況IDが指定された場合も、
`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`
として扱う。

他利用者のデータが
存在すること自体を
レスポンスから判別できないようにする。

---

### 11.4 X-User-Id

以下を検証する。

- 指定されていること
- API共通方針で定めたID形式であること
- 指定された利用者が存在すること
- 指定された利用者が論理削除されていないこと

`X-User-Id`が指定されていない場合は、
`USER_CONTEXT_REQUIRED`
として扱う。

形式が不正な場合は、
`INVALID_USER_ID`
として扱う。

指定された利用者が存在しない場合、
または論理削除されている場合は、
`USER_NOT_FOUND`
として扱う。

---

### 11.5 確定状態

月末資産状況の確定状態は、
取得可否の条件としない。

以下のどちらも取得できる。

```text
confirmed = true
confirmed = false
```

本APIでは、
確定可否および
確定解除可否の検証は行わない。

---

### 11.6 クエリパラメータ

本APIでは、
クエリパラメータを定義しない。

未定義のクエリパラメータが
指定された場合の扱いは、
API共通方針に従う。

---

### 11.7 リクエストボディ

本APIでは、
リクエストボディを使用しない。

リクエストボディが
指定された場合の扱いは、
API共通方針に従う。

---

## 12. 業務ルール

- 操作対象利用者に属する月末資産状況のみ取得する。
- 指定された月末資産状況が他の利用者に属する場合は、存在しないものとして扱う。
- 確定済み・未確定の月末資産状況をともに取得対象とする。
- 月末資産状況の確定状態は、データベースに保持されている状態をそのまま返却する。
- 本APIでは、月末資産状況の確定可否を判定しない。
- 本APIでは、月末資産状況の確定解除可否を判定しない。
- 本APIでは、月末資産残高の明細を返却しない。
- 本APIでは、商品別月末評価額の明細を返却しない。
- 月末資産残高の確認は、BAL-001 月末資産残高一覧取得APIを使用する。
- 商品別月末評価額の確認は、VAL-001 商品別月末評価額一覧取得APIを使用する。
- 本APIの実行によって、月末資産状況および関連データは変更しない。
- 未確定の月末資産状況は詳細表示できるが、正式な現在資産状況および目的達成判定には利用しない。


月末資産状況の取得条件は、
以下とする。

```text
id = snapshotId
AND
user_id = 操作対象利用者ID
```

対象となる月末資産状況が
存在しない場合は、
`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`
として処理を終了する。

本APIは参照のみを行うため、
明示的なデータベーストランザクションは使用しない。

以下のデータは変更しない。

- 月末資産状況
- 月末資産残高
- 商品別月末評価額
- 資産口座
- 保有商品
- 利用可能資産設定

---

## 15. 排他制御

本APIは参照のみを行うため、
明示的な排他制御は行わない。

以下は使用しない。

- 悲観ロック
- 楽観ロック
- 行ロック

詳細取得中に
別のリクエストによって
月末資産状況の確定または
確定解除が行われた場合は、
データベースから取得できた時点の
確定状態を返却する。

Phase1では、
参照処理と他の更新処理との間で
厳密なスナップショット整合性は保証しない。

## 17. レスポンス項目

| 項目 | 型 | NULL | 説明 |
|---|---|:---:|---|
| `data` | object | × | 月末資産状況 |
| `data.id` | string | × | 月末資産状況ID |
| `data.targetYearMonth` | string | × | 対象年月（YYYY-MM） |

月末資産状況IDは、
API共通方針に従って
文字列として返却する。

`YYYY-MM`形式で返却する。

月末資産状況に保持されている

以下の情報は返却しない。

- `user_id`
- `month_end_asset_balances`
- `month_end_holding_values`
- `asset_accounts`
- `holding_assets`
- `asset_account_available_settings`
- `created_at`
- `updated_at`

BAL-001 月末資産残高一覧取得APIを使用する。

商品別月末評価額の詳細確認には、

## 19. HTTPステータス

| HTTPステータス | 条件 |
|---:|---|
| `200 OK` | 月末資産状況詳細の取得に成功した |
| `400 Bad Request` | 利用者コンテキストが未指定、または利用者IDの形式が不正である |
| `404 Not Found` | 指定された利用者または月末資産状況が存在しない |
| `422 Unprocessable Entity` | `snapshotId`の形式が不正である |
| `500 Internal Server Error` | 想定外のサーバーエラーが発生した |

---

### 19.1 200の扱い

指定された月末資産状況が
操作対象利用者に属している場合は、
`200 OK`
を返却する。

確定済み・未確定の
どちらの場合も正常終了とする。

---

### 19.2 400の扱い

以下の場合は、
`400 Bad Request`
を返却する。

- `X-User-Id`が指定されていない
- `X-User-Id`の形式が不正である

---

### 19.3 404の扱い

以下の場合は、
`404 Not Found`
を返却する。

- 指定された利用者が存在しない
- 指定された利用者が論理削除されている
- 指定された月末資産状況が存在しない
- 指定された月末資産状況が他の利用者に属している

他利用者に属する月末資産状況を指定した場合も、
`404 Not Found`とすることで
利用者境界を越えたリソースの存在を公開しない。

---

### 19.4 422の扱い

`snapshotId`が
API共通方針で定めたID形式に
一致しない場合は、
`422 Unprocessable Entity`
を返却する。

---

## 20. エラーコード

| エラーコード | HTTPステータス | 条件 | 再試行 |
|---|---:|---|:---:|
| `USER_CONTEXT_REQUIRED` | 400 | `X-User-Id`が指定されていない | × |
| `INVALID_USER_ID` | 400 | 利用者IDの形式が不正である | × |
| `USER_NOT_FOUND` | 404 | 指定された利用者が存在しない、または論理削除されている | × |
| `VALIDATION_ERROR` | 422 | `snapshotId`の形式が不正である | × |
| `MONTH_END_ASSET_SNAPSHOT_NOT_FOUND` | 404 | 指定された月末資産状況が存在しない、または他の利用者に属している | × |
| `INTERNAL_SERVER_ERROR` | 500 | 想定外のサーバーエラーが発生した | ○ |

エラーコードの正式な定義は、
`error-codes.md`
に従う。

`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`では、
対象リソースが存在しない場合と
他利用者に属している場合を区別しない。

## 21. 冪等性

本APIは、
HTTP GETを使用する
参照専用APIである。

同一条件で複数回リクエストしても、
本API自身によって
サーバー上のデータは変更されない。

そのため、
本APIは冪等である。

本APIの実行によって、
以下の処理は行わない。

- 月末資産状況の作成
- 月末資産状況の更新
- 月末資産状況の確定
- 月末資産状況の確定解除
- 月末資産残高の登録・更新
- 商品別月末評価額の登録・更新

リクエスト間に
他のAPIによって
月末資産状況の確定状態などが変更された場合は、
取得結果が変化する可能性がある。

これは、
本APIの冪等性を損なうものではない。

参照専用APIであるため、
`Idempotency-Key`は使用しない。

  - 月末資産状況は対象年月および確定状態を保持する
  - 確定済み・未確定の月末資産状況を確認できる

- 月末資産状況の確定
  - 月末資産状況は確定状態を保持する
  - 確定済みの月末資産状況は正式な資産状況として扱う
  - 未確定の月末資産状況は正式な現在資産状況および目的達成判定には利用しない

- 利用者境界
  - 操作対象利用者に属する月末資産状況のみ取得する
  - 他の利用者に属する月末資産状況は取得できない
  - 他利用者に属する月末資産状況を指定した場合は、存在しないものとして扱う

具体的な章番号は、
`functional-requirements.md`の
最新定義に従う。

## 24. 設計上の補足

### 24.1 詳細取得APIを分離する理由

月末資産状況一覧取得APIは、複数の対象年月を一覧表示する責務を持つ。

本APIは、指定された1件の月末資産状況を取得する責務を持つ。

一覧取得と詳細取得を分離することで、APIの責務を明確にする。

---

### 24.2 明細を含めない理由

月末資産状況には、複数の月末資産残高および商品別月末評価額が紐づく可能性がある。

これらを詳細取得APIへ含めると、レスポンス構造が複雑になり、必要のない画面でも大量の明細を取得する可能性がある。

そのため、本APIでは月末資産状況そのものの情報だけを返却する。

---

### 24.3 確定済み・未確定を両方取得できる理由

月末資産状況詳細画面は、確定済みデータの確認だけでなく、未確定データの入力作業にも使用する。

そのため、確定状態を取得条件としない。

---

### 24.4 利用者境界外を404とする理由

他の利用者に属する月末資産状況を指定した場合に権限エラーとして返却すると、対象リソースの存在を推測できる可能性がある。

そのため、利用者境界外の場合も存在しないものとして扱い、`MONTH_END_ASSET_SNAPSHOT_NOT_FOUND`を返却する。

---

### 24.5 確定可否を返却しない理由

月末資産状況を確定できるかどうかは、`confirmed`だけでは決定できない。

確定時には、以下のような業務条件を確認する必要がある。

- 必要な月末資産残高が登録されている
- 必要な商品別月末評価額が登録されている
- 対象年月の確定順序を満たしている

そのため、本APIでは`canConfirm`などの派生フラグを返却しない。

確定可否は、SNP-004 月末資産状況確定APIで最新状態をもとに判定する。

---

### 24.6 確定解除可否を返却しない理由

確定解除できるのは、業務ルール上、最新の確定済み月末資産状況に限られる。

詳細取得時に確定解除可否を返却しても、その後に別の対象年月が確定される可能性がある。

そのため、本APIでは`canUnconfirm`などの派生フラグを返却しない。

確定解除可否は、SNP-005 月末資産状況確定解除APIで実行時に判定する。

---

### 24.7 confirmedAtを返却しない理由

Phase1の詳細画面では、月末資産状況が確定済みか未確定かを確認できればよい。

確定日時そのものを画面表示や業務判断に使用しないため、本APIでは`confirmedAt`を返却しない。

将来、確定日時を履歴表示や監査情報として利用する場合は、レスポンスへの追加を再検討する。

---

### 24.8 GETを採用する理由

本APIは、月末資産状況の詳細を参照するだけであり、サーバー側の状態を変更しない。

そのため、HTTPメソッドには`GET`を採用する。

本APIは冪等であり、`Idempotency-Key`は使用しない。

---

### 24.9 関連テーブルをJOINしない理由

本APIで必要な情報は、`month_end_asset_snapshots`のみで取得できる。

月末資産残高、商品別月末評価額、資産口座および保有商品をJOINする必要はない。

不要なJOINを避けることで、取得処理を単純に保つ。

---

### 24.10 キャッシュを採用しない理由

月末資産状況の確定および確定解除によって、`confirmed`は変更される。

キャッシュを導入すると、状態変更時のキャッシュ無効化処理が必要になる。

Phase1では、詳細取得頻度およびデータ量が限定的であるため、アプリケーションキャッシュは採用しない。

---
