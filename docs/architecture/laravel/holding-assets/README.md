# 保有商品 Laravelアーキテクチャ設計

## 1. 概要

本ディレクトリでは、
保有商品に関するAPIをLaravelで実装する際の
アーキテクチャおよび責務分離方針を定義する。

対象APIは以下とする。

* HLD-001 保有商品一覧取得
* HLD-002 保有商品登録
* HLD-003 保有商品詳細取得
* HLD-004 保有商品更新
* HLD-005 保有商品無効化

保有商品は、利用者が保有する預金、投資商品などを
資産口座に紐付けて管理するための情報とする。

商品単位で残高を記録する資産口座では、
保有商品が月末評価額を管理する単位となる。

---

## 2. アーキテクチャ方針

保有商品APIでは、Laravel共通アーキテクチャに従い、
主に以下の責務へ分離する。

```text
Request
    ↓
Middleware
    ↓
Action
    ↓
UseCase
    ├─ Query
    └─ Repository
    ↓
Result DTO
    ↓
API Resource
    ↓
Responder
```

各レイヤーの責務を明確にし、
HTTP処理、業務ルール、参照処理、永続化処理および
レスポンス生成を分離する。

---

## 3. 利用者境界

保有商品は利用者単位で管理する。

すべての参照・更新処理では、
共通の利用者コンテキストから取得した利用者IDを使用し、
他利用者の保有商品を操作できないようにする。

`userId`はリクエストから直接受け取らない。

また、保有商品の所属する資産口座についても、
操作対象利用者との帰属関係を確認する。

---

## 4. 無効化と論理削除

保有商品の利用停止は、
論理削除ではなく利用状態の変更として扱う。

```text
enabled = true
    ↓
enabled = false
```

無効化された保有商品は新しい資産記録などの対象外とするが、
過去情報を参照できる状態は維持する。

`deleted_at`による論理削除とは明確に区別する。

---

## 5. 実装上の共通方針

* DBカラム名をAPIへ直接公開しない
* JSONフィールド名はcamelCaseとする
* IDはレスポンス上stringとして扱う
* Queryは参照処理を担当する
* Repositoryは登録・更新処理を担
