# 手取り収入 Laravelアーキテクチャ設計

## 1. 概要

本ディレクトリでは、

手取り収入に関するAPIをLaravelで実装する際の

アーキテクチャおよび責務分離方針を定義する。

対象APIは以下とする。

* INC-001 手取り収入一覧取得
* INC-002 手取り収入登録
* INC-003 手取り収入詳細取得
* INC-004 手取り収入更新
* INC-005 平均手取り収入取得

手取り収入は、

利用者ごとに対象年月単位で管理し、

同一利用者・同一対象年月について

1件のみ登録できる。

収入が発生しなかった年月についても、

未登録とは区別し、

金額0円の手取り収入として登録する。

## 2. アーキテクチャ方針

Laravel実装では、

ActionをHTTPリクエストの入口とし、

処理内容に応じて以下へ責務を分離する。

```text
Request
    ↓
Action
    ↓
UseCase
    ↓
Query / Repository / Domain Service
    ↓
Responder
    ↓
API Resource
```

Form Requestは入力値の形式や単項目バリデーションを担当し、

データベースの状態に依存する業務ルールはUseCaseで制御する。

Queryは参照処理、

Repositoryは登録・更新などの永続化を担当する。

平均手取り収入などの業務計算は、

Domain Serviceへ分離する。

すべてのデータアクセスでは、

利用者コンテキストから取得した利用者IDを条件に含め、

他利用者のデータを参照・更新できないようにする。

## 3. 手取り収入登録・更新

登録および更新では、

対象年月の重複をアプリケーションで確認するとともに、

データベースのUNIQUE制約を

最終的な重複防止手段として使用する。

永続化処理はトランザクション内で実行し、

同時実行による制約違反も

共通の業務エラーへ変換する。

## 4. 平均手取り収入

平均手取り収入は、

判定対象年月直前の連続する3か月の

手取り収入から算出する。

算出結果はデータベースへ保存せず、

取得時点のデータから都度算出する。

必要な3か月のうち1か月以上が未登録の場合は、

`NET_INCOME_DATA_INSUFFICIENT`として扱う。

金額0円として登録されたデータは、

有効な算出対象に含める。
