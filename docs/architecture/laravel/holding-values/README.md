# 商品別月末評価額 Laravelアーキテクチャ設計

## 1. 概要

本ディレクトリでは、
商品別月末評価額に関するLaravel実装方針を定義する。

商品別月末評価額は、
残高記録単位が商品単位である資産口座について、
保有商品ごとの月末時点の評価額を管理する。

対象となる月末資産状況は `snapshotId` によって特定し、
登録・更新時は月末資産状況が未確定であることを前提とする。

また、資産口座および保有商品の利用可否は、
現在の状態ではなく、
月末資産状況の `target_year_month` 時点の状態を基準に判定する。

口座単位で残高を記録する資産口座については、
商品別月末評価額ではなく、
月末資産残高（BAL系API）で管理する。

---

## 2. API一覧

| ID | 機能 | 概要 |
|---|---|---|
| VAL-001 | 商品別月末評価額一覧取得 | 指定した月末資産状況に紐づく商品別月末評価額を取得する |
| VAL-002 | 商品別月末評価額登録 | 未登録の商品別月末評価額を新規登録する |
| VAL-003 | 商品別月末評価額更新 | 登録済みの商品別月末評価額の `value` を更新する |

VAL-002では既存データを上書きせず、
VAL-003では未登録データを新規作成しない。

登録と更新の責務を明確に分離し、
`updateOrCreate` 等によって両方の処理を兼ねない。

---

## 3. 共通実装方針

- `X-User-Id` による利用者境界を必ず適用する
- 登録・更新は未確定の月末資産状況に対してのみ行う
- 資産口座の残高記録単位が商品単位であることを確認する
- `target_year_month` 時点の資産口座・保有商品の状態を基準に判定する
- `value` は日本円の整数値として扱い、`0` を有効値とする
- Queryは参照、Repositoryは登録・更新を担当する
- 登録・更新処理はトランザクション内で実行する
- APIレスポンスはcamelCaseへ変換する
- Laravel・PostgreSQLの内部例外をAPIレスポンスへ直接公開しない
