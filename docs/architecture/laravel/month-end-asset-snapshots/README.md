# 月末資産状況 Laravelアーキテクチャ設計

## 1. 概要

本ディレクトリでは、
月末資産状況に関するAPIをLaravelで実装する際の
アーキテクチャおよび責務分離方針を定義する。

対象APIは以下とする。

- SNP-001 月末資産状況一覧取得
- SNP-002 月末資産状況作成
- SNP-003 月末資産状況詳細取得
- SNP-004 月末資産状況確定
- SNP-005 月末資産状況確定解除

月末資産状況は、
対象年月ごとの資産情報を管理する親リソースであり、
月末資産残高および商品別月末評価額を紐づけて管理する。

未確定状態では入力内容を編集可能とし、
確定後は正式な月末資産状況として扱う。

---

## 2. Laravel実装方針

Laravelでは、
以下の責務を分離する。

```text
Request
  ↓
Action
  ↓
UseCase
  ↓
Query / Repository / Validator
  ↓
Responder
  ↓
API Resource
```

ActionはHTTP層の受付に限定し、
業務ロジックを直接記述しない。

UseCaseは、
各APIの処理順序および業務フローを制御する。

Queryは参照処理と利用者境界を担当し、
月末資産状況取得時は必ず
操作対象利用者IDを検索条件へ含める。

Repositoryは、
作成・確定・確定解除などの
永続化処理を担当する。

確定・確定解除では、
複数の業務条件をUseCaseへ集中させず、
必要に応じて専用Validatorへ分離する。

---

## 3. 状態管理

月末資産状況は、
以下の2状態を持つ。

```text
未確定
  ↓ 確定
確定済み
  ↓ 確定解除
未確定
```

作成直後は必ず未確定とする。

確定時は、
確定順序、
必要な月末資産残高、
必要な商品別月末評価額を確認する。

確定解除は、
時系列上の整合性を維持するため、
最新の確定済み月末資産状況のみ許可する。

確定解除しても、
登録済みの月末資産残高、
商品別月末評価額、
目的達成判定履歴は削除しない。

---

## 4. トランザクション・排他制御

参照APIでは、
原則として明示的なトランザクションを使用しない。

作成APIでは、
重複確認と登録をトランザクション内で実行し、
`user_id` と `target_year_month` の
UNIQUE制約を最終的な重複防止手段とする。

確定・確定解除では、
対象レコードを `lockForUpdate()` で取得し、
業務条件の最終確認から状態更新までを
同一トランザクション内で実行する。

---

## 5. 共通方針

内部例外、
SQL、
スタックトレース、
PostgreSQLの内部情報は
APIレスポンスへ公開しない。

API Resourceを使用し、
DBカラムをそのまま外部へ返却しない。

`target_year_month` は
`YYYY-MM` 形式の年月を表す業務値として扱い、
Phase1ではCarbonへのdate castを行わない。
