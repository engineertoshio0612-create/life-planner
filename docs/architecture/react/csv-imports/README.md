# CSVインポート Reactアーキテクチャ設計

## 1. 概要

本ディレクトリでは、CSVインポート関連APIをReact・TypeScriptから利用する際のアーキテクチャおよび責務分離方針を定義する。

対象APIは以下とする。

- CSV-001 月末資産残高CSVテンプレート取得
- CSV-002 月末資産残高CSVプレビュー
- CSV-003 月末資産残高CSV登録
- CSV-004 商品別月末評価額CSVテンプレート取得
- CSV-005 商品別月末評価額CSVプレビュー
- CSV-006 商品別月末評価額CSV登録

CSVインポートでは、テンプレート取得、プレビュー、登録をそれぞれ独立した処理として扱う。

```text
テンプレート取得
    ↓
利用者がCSV編集
    ↓
CSVファイル選択
    ↓
プレビュー
    ↓
内容・エラー確認
    ↓
canImport = true
    ↓
登録
    ↓
関連データ再取得
```

React側では、CSVの正式な解析、入力値検証、業務ルール検証、重複判定などを行わず、バックエンドの判定結果を正とする。

プレビューでは、バックエンドから返却された`canImport`、行データ、エラー情報を画面表示および登録操作の制御に利用する。`canImport`をReact側で再計算しない。

登録時は、プレビューで使用した同一の`File`を再送する。プレビュー結果からCSVを再構築したり、`previewId`などを使用したりしない。

```text
File
    ↓
Preview API
    ↓
Preview Result + File保持
    ↓
Create APIへ同じFileを再送
```

プレビュー時の`canImport = true`は登録成功を保証しない。登録APIでは実行時点の最新状態をバックエンドが再検証するため、競合や入力エラーが返却されることを考慮する。

TanStack Queryでは、プレビューおよび登録を利用者操作によって実行するMutationとして扱う。登録成功後は、月末資産状況や月末資産残高、商品別月末評価額など、影響を受けるQuery Cacheを無効化し、サーバーから最新状態を再取得する。

CSVファイル、プレビュー結果、ローディング状態、エラー表示などの画面状態はフロントエンドで管理する。一方、利用者境界、CSV仕様、業務整合性、トランザクション、重複防止などの最終保証はバックエンドの責務とする。

個別APIの詳細な利用方法、型定義、Mutation、エラー処理およびCache無効化方針については、各APIの設計書を参照する。
