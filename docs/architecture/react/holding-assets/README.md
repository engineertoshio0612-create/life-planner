# 保有商品 Reactアーキテクチャ設計

## 1. 概要

本ディレクトリでは、保有商品に関するAPIをReact・TypeScriptから利用する際のフロントエンドアーキテクチャおよび責務分離方針を定義する。

対象APIは以下とする。

* HLD-001 保有商品一覧取得
* HLD-002 保有商品登録
* HLD-003 保有商品詳細取得
* HLD-004 保有商品更新
* HLD-005 保有商品無効化

保有商品は資産口座に所属し、商品単位で資産を管理する際の基本単位として扱う。

## 2. アーキテクチャ方針

React実装では、画面表示、フォーム状態管理、API通信およびサーバー状態管理の責務を分離する。

```text
Page / Component
    ↓
Form / UI
    ↓
Query / Mutation Hook
    ↓
API Client
    ↓
API
```

APIのリクエストおよびレスポンスはTypeScriptの型として定義し、API契約との整合性を保つ。

サーバー状態の取得・更新にはTanStack Queryを利用し、一覧・詳細取得はQuery、登録・更新・無効化はMutationとして扱う。

登録・更新・無効化の成功後は、関連するQuery Cacheを無効化または再取得し、サーバー側の最新状態を画面へ反映する。

## 3. フォーム・業務ルール

フロントエンドで判定可能な入力形式は送信前に検証する。

一方、利用者境界、資産口座の利用状態、残高記録単位、商品名重複など、サーバー状態に依存する業務ルールはAPIの判定結果を正とする。

HLD-004では変更された項目のみを更新対象とし、所属資産口座、利用開始年月および利用状態は編集しない。

## 4. 無効化

保有商品の無効化は通常更新とは異なる業務操作として扱い、HLD-005専用のMutationおよびAPI Clientを使用する。

無効化時に`isEnabled`、`disabled`、`deletedAt`などの状態値を送信しない。

Phase1では再有効化UIおよびOptimistic Updateを必須とせず、API成功後にQuery Cacheを更新してサーバー状態へ同期する。

## 5. 個別設計

各API固有の画面処理、型定義、Query・Mutation、API Client、キャッシュ制御およびエラー処理については、各APIのReactアーキテクチャ設計を参照する。
