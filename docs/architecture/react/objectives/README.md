# 目的 Reactアーキテクチャ設計

## 1. 概要

本ディレクトリでは、
目的に関するAPIをReact・TypeScriptから利用する際の
アーキテクチャおよび実装方針を定義する。

対象APIは以下とする。

* OBJ-001 目的一覧取得
* OBJ-002 目的登録
* OBJ-003 目的詳細取得
* OBJ-004 目的更新
* OBJ-005 目的無効化
* OBJ-006 目的達成判定

目的では、達成したい内容、実施予定年月、
必要支出額、メモおよび利用状態を扱う。

---

## 2. React実装方針

目的関連機能では、主に以下の責務へ分離する。

```text
Page
    ↓
Component
    ↓
Query / Mutation Hook
    ↓
API Client
    ↓
Laravel API
```

Pageは画面単位の状態や画面遷移を管理し、
Componentは表示および利用者操作を担当する。

API通信処理はAPI Clientへ集約し、
コンポーネントから直接`fetch`や`axios`を実行しない。

サーバー状態はTanStack Queryで管理する。

参照APIであるOBJ-001・OBJ-003はQuery、
サーバー状態を変更するOBJ-002・OBJ-004・OBJ-005・OBJ-006は
Mutationとして扱う。

Mutation成功後は、影響するQueryを
再取得または無効化し、
サーバー側の最新状態と画面表示の整合性を保つ。

---

## 3. 利用者コンテキスト

操作対象利用者は共通の利用者コンテキストで管理し、
API Clientから`X-User-Id`として送信する。

各APIのRequest型やComponentへ
`userId`を個別に持たせない。

利用者切替時は、前利用者の目的情報が
新しい利用者へ表示されないようCacheを管理する。

---

## 4. 共通データ方針

APIから返却されるIDは`string`として扱う。

年月は`YYYY-MM`形式の文字列、
金額は日本円の整数値として扱う。

バックエンドで算出された資産額、平均手取り収入、
目的達成判定結果などをReact側で独自に再計算しない。

目的の`enabled`は業務上の利用状態として扱い、
論理削除とは区別する。

無効化された目的は新しい目的達成判定の対象外とするが、
過去の目的情報および判定履歴は参照可能とする。

個別API固有の型、Query Key、Mutation、
Cache更新、画面制御およびエラー処理については、
各APIの設計書で定義する。
