# 月末資産状況 Reactアーキテクチャ設計

## 1. 概要

本ディレクトリでは、
月末資産状況に関するAPIを
React・TypeScriptから利用する際の
画面制御、型定義、状態管理、
エラー処理および再取得方針を定義する。

対象APIは以下とする。

- SNP-001 月末資産状況一覧取得
- SNP-002 月末資産状況作成
- SNP-003 月末資産状況詳細取得
- SNP-004 月末資産状況確定
- SNP-005 月末資産状況確定解除

月末資産状況は、
対象年月ごとの月末資産残高および
商品別月末評価額を管理する
親リソースとして扱う。

---

## 2. React・TypeScript実装方針

APIのIDは文字列として扱い、
フロントエンド側で
数値計算には使用しない。

`targetYearMonth` は
`YYYY-MM` 形式の年月を表す
業務値として文字列で保持し、
JavaScriptの `Date` へ
不必要に変換しない。

`confirmed` は
月末資産状況の確定状態を表す。

```text
false → 未確定
true  → 確定済み
```

フロントエンドでは、
`confirmed` に応じて
ボタン表示や編集可否などの
補助的な画面制御を行ってよい。

ただし、
確定可否・確定解除可否などの
業務ルールを独自に完全再現せず、
最終判断はバックエンドAPIへ委ねる。

---

## 3. データ取得・状態管理

月末資産状況、
月末資産残高、
商品別月末評価額は
それぞれ別APIとして扱う。

一覧・詳細取得中は
ローディング状態を表示し、
利用者や `snapshotId` が変更された際に
以前の取得結果を
現在の対象として表示しない。

作成・確定・確定解除成功後は、
関連する一覧・詳細データを再取得する。

TanStack Query等を利用する場合は、
対象クエリをinvalidateして
最新状態を反映する。

---

## 4. 更新操作

作成・確定・確定解除中は、
対象ボタンを非活性化し、
意図しない二重送信を抑止する。

ただし、
重複登録防止や排他制御などの
最終的な整合性保証は
バックエンドへ委ねる。

確定解除後も、
登録済みの月末資産残高、
商品別月末評価額、
目的達成判定履歴は
フロントエンド側で削除・初期化しない。

---

## 5. エラー処理

APIから返却された
独自エラーコードに応じて、
入力エラー、
業務状態エラー、
利用者選択への誘導、
共通エラー表示を使い分ける。

存在しないデータと
他利用者に属するデータについて、
バックエンドが同一エラーとして返す場合は、
フロントエンドでも原因を区別しない。
